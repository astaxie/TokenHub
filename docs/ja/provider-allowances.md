# プロバイダーのクォータと特典

**プロバイダー → クォータと特典**を開きます。上流アカウントを管理する画面です。顧客とチームの予算は引き続き「クォータポリシー」で管理します。

## 収集

クォータのキャッシュは推論の稼働確認から独立しています。通常のリクエストはキャッシュを使い、`capCareful` を有効にした場合だけ Magpie の規則で事前照会します。クラスタ内で調整されたバックグラウンド処理が、最大四つのアカウントを並列で更新します。更新間隔は30秒から一日で、初期値は60秒です。失敗しても前回成功時の値と日時を保持します。利用可能、使い切り、不明、照会失敗を区別します。10分を超えたデータ、必須ウィンドウの欠落、経過したリセット日時は空き容量の根拠にしません。

サブスクリプションは既存のアダプターを使います。APIキーは残高APIを自動認識し、別の収集元も設定できます。Fusecode、DeepSeek、Moonshot、OpenRouter、SiliconFlow、StepFun、AiHubMix、ModelScope、GLM/Z.ai、Kimi Code、OpenCode Go、MiniMax、Command Code、Ollama、Mistral、NewAPI、Sub2API、およびVolcengine・Alibaba・Tencentのクラウドプランのプリセットがあります。提供元が照会を許可するキーと権限が必要です。Tencentはプラン一覧と各詳細を読み、詳細照会に失敗した場合は一覧の値を保持します。Mistralはキーの種類を確認してAPIまたはVibeの予算を選びます。StepFunのWebプランは暗号化ヘッダー内の有効なセッションが必要です。

Fusecodeはプリセットを選ぶか、Magpieの次の設定を入力します。

```text
URL: https://fusecode.ai/v1/usage
Expression: $remaining; Week: subscription.weekly_usage_usd / subscription.weekly_limit_usd %; Month: subscription.monthly_usage_usd / subscription.monthly_limit_usd %
```

ラベル、複数部分、通貨、割合、算術、集合の絞り込みと `sum`、`min`、`max`、`count` に対応します。一部だけ読めない場合はその部分を不明にし、すべて読めない場合は照会失敗にします。構造化ウィンドウには使用量、上限、単位、リセットと期限、対象・除外モデル、プールの所属を保存します。提供元が返さないリセット日時は補いません。

アカウントのキー、専用の暗号化トークン、暗号化ヘッダーを使えます。URLとヘッダーの `{key}` は実行時に置き換えます。保存後のヘッダー値は伏せられます。保存済みヘッダーの名前を変更したら、値の再入力が必要です。専用トークンは空欄で維持し、削除を選ぶと消去します。既存のURL、DNS、リダイレクト、プロキシ制限を適用します。クラウド署名の送信先は固定です。Alibabaのコンソールトークンは暗号化して20分間キャッシュします。

### Magpie の残高とクォータ設定を直接移行する

Magpie `47b51c8` の構文、既定値、クォータ動作を基準にします。主な項目は残高照会 URL、GET/POST、残高フィールド、アカウント残高です。互換モードの選択は不要です。追加の収集項目は折りたたみ表示します。

API キーのプロバイダー URL から既知の残高・プラン API を認識します。不明な中継サービスは `/v1/usage`、`/api/usage/token` の順で探索します。成功は24時間、該当なしは6時間、接続失敗は5分間キャッシュします。共有キャッシュは暗号化し、アカウントと設定の変更を検証します。`noBalanceProbe` で探索を無効にできます。保存前の照会は現在のフォームで再探索し、見つかった URL を入力できます。クォータ、履歴、特典設定は保存しません。

「Magpie クォータ設定をインポート」で完全な `providers.json`、配列、単一プロバイダーと、任意の `settings.json` を読み込みます。プロバイダーとアカウントを選びます。アカウント省略時は現在のキーの Magpie ID（SHA-256 の先頭5バイト）または名前で照合し、特定できない場合は選択を求めます。フォームに入力した設定は保存後に適用します。

| 元のフィールド | 移行する動作 |
| --- | --- |
| `balanceURL`、`balancePath`、`balanceMethod`、`balanceToken`、`headers`、`noBalanceProbe` | 元の URL、式、メソッド、トークン、ヘッダー、探索設定 |
| `accountCaps`、`accountWindowCaps`、`accountWindowAmounts` | アカウント・ウィンドウの割合または固定使用量。100 はウィンドウ固有の上限なし |
| `capStop`、`capCareful` | 全アカウント制限時は429、上限付近では再照会し不明時は保留 |
| `keySpendCaps` | 現地の日・月または累計の費用上限。累計上限変更時も開始時刻を保持 |
| `keyOwnBalances` | USD/CNY 残高、週次・月次補充、開始時刻付きの期限付き残高 |
| `codexNoCredits`、`codexCreditsFirst`、`codexCreditsLast` | クレジット使用を既定で許可し、禁止・優先・最後を選択 |
| `codexAutoReset`、`codexAutoResetOnly`、`codexResetLead` | 消尽時・期限前のリセット。分単位、既定は無効、週1回 |
| `usageAlert`、`balanceAlert`、`resetReminder` | 使用率・低残高・リセット通知。0 は無効、通知は時間単位 |
| `accessKeyID`、`secretAccessKey` | 火山・Tencent・Alibaba の独立したクラウド認証情報を暗号化 |

アカウントトークンの認証方式は保持し、JWT には Bearer を付け、その他はそのまま送ります。API キーと同じトークンはキー認証を使います。`{token}` を含む元のプレースホルダーは推論 API キーを指します。POST は既定で本文なしです。既知の中継 API のフィールドは省略でき、アカウントトークンや明示的な Authorization/Cookie がなければ対応するキー API を使用します。

補充は現地の午前0時に元の残高へ戻し、繰り越しません。指定日がない月は月末を使います。期限日は当日を含み、期限の早い残高から消費します。手動残高は負値を表示でき、最新のプロバイダー通貨残高を優先します。CNY は設定済み為替レートを使い、費用があってレート不明なら残高も不明です。

通常のリクエストはキャッシュを使います。`capCareful` 有効時は上限まで5ポイント以内で15秒以上古い値、または5分以上古い値を再照会します。待機は最大10秒、失敗後の再試行は15秒以上空けます。通知はリセット時刻の10分以内のずれを許容して周期ごとに重複を排除し、期限前のリセットカードも含みます。Tencent の TeamId 省略時は、単一プランをアカウントの制限に使います。複数プランは参考ウィンドウとして別々に表示し、合算しません。TeamId で一つを指定することもできます。

推論キーとルートは置き換えません。TokenHub はプロジェクト権限、暗号化、共有 DB、HTTP 制限を担当します。デスクトップ通知は既存の通知チャネルに対応付けます。インポートした有効な特典設定は保存後に適用されます。開発・検証は合成アカウントだけで行います。


## 使用と特典の方針

モデルとアカウントの選択を別々に設定します。並べ替えと停止の対象は、プロジェクトとキーが許可されたルート、モデル、優先度の候補だけです。クォータ優先、期限優先、使用量が少ない順、使い切ってから切り替えの四方式があります。初期値は既存の順序を維持します。

アカウントまたはウィンドウの上限で、提供元の上限より前に停止できます。ウィンドウ上限の名前は、前後の空白と大文字・小文字の違いを除いて一意にします。重複すると保存を止め、入力内容を保持します。金額は報告された単位のまま扱います。参考ウィンドウは明示した上限以外には使いません。プールの上限は所属モデルだけに適用します。ウォレットの消費上限は独立した永続カウンターで管理します。チャージ、古い観測、再起動、履歴の削除では消費量が戻りません。リセットのないウォレットはUTCの日単位です。

報告されたクレジットは既定で許可し、禁止、優先、最後に使用も選べます。同じ許可済みルートと優先度の範囲で適用します。クレジットや自動リセットでユーザーの上限を回避できません。

Codexの自動リセットは初期状態で無効です。週のクォータを使い切った場合、カードの期限前、または両方を選べます。週の使い切りには実際の呼び出し失敗と、そのリクエストで許可された候補だけを記録した最近の実行記録が必要です。利用可能または不明の候補が残る場合は消費しません。期限前の使用はウィンドウに使用量がある場合だけで、期限の近いカードを優先します。初期値は30分前、週一回です。永続的な予約と既存の冪等実行器で重複消費を防ぎます。結果が不明なら自動再試行を停止します。操作記録は画面で確認できます。

手動残高はバックグラウンドで計算し、設定の版を確認したキャッシュから読み取ります。計算失敗時は前回の値と取得時刻を保持し、古い値や未計算の値は不明として扱います。手動ウォレットは開始残高、期限付き付与額、定期補充に対応し、期限の近い付与額から消費します。日付による補充は繰り越しません。従来の固定間隔設定は繰り越しを維持します。推定から差し引くのはゲートウェイに記録された提供元原価だけです。外部の消費は含めません。CNYは設定済み為替レートを使い、消費後にレートがなければ不明です。その他の単位は換算率を指定します。共有ウォレットは明示的に選択し、元のアカウントの同一性に固定します。残高が同じだけでは共有しません。共有の手動ウォレットは関連アカウントのゲートウェイ消費を合計し、モデル上限は独立して扱います。アカウント認証またはAPIキーの置換時は古い設定と観測を消去します。

## 履歴、通知、API

変化のあった成功観測を45日間保持します。ウィンドウ別に推移を表示し、観測された残高減少から残り日数を推定します。異なる通貨とクレジット単位は合算しません。高使用率、低残高、リセット前の未使用クォータを通知できます。同じ期間の重複を防ぎ、回復やチャージ後に再び有効にします。既存の通知先を選ぶと配信し、未選択なら通知画面に記録します。送信前に永続的に取得するため、結果不明の自動重複配信はありません。

管理者APIにはプロバイダー権限が必要です。

- `GET /api/admin/provider-allowances` と `/presets`：キャッシュと収集プリセット。
- `GET|PUT /api/admin/provider-resources/{id}/allowance/config`：秘匿済み設定とリビジョンによる更新。
- `GET /api/admin/provider-resources/{id}/allowance/history` と `/events`：件数を制限した履歴と操作記録。
- `POST /api/admin/provider-resources/{id}/allowance/refresh`：上流の明示的更新。
- `POST /api/admin/provider-resources/{id}/allowance/preview` と `/import-magpie`：保存せずにフォームを照会、または元の設定を入力。

プロジェクトAPIキーは `GET /v1/allowance?model=<alias>` を使えます。`wait_seconds=0..60` を指定するとキャッシュの更新を待ちます。許可済みルートの利用可否だけを集計し、提供元の識別情報、残高、設定は返しません。待機中に提供元を呼びません。

スキーマ拡張12は、設定、セッション、履歴、特典イベント、ウォレットカウンターと索引を追加します。凍結された採用ベースラインは変えません。環境変数の追加はありません。[データベースの進化](database-evolution.md)を参照してください。

## Magpieの参照元

式、プラン応答、クラウド署名の処理はMagpieの `47b51c8225a66e753dd249cb782472b0dcbee6c4` を参照しています。保存、プロジェクト権限、バックグラウンド処理、カウンター、データベース調整、UIはTokenHub向けに実装しています。デスクトップのログイン切り替え、トレイ、MagpieのローカルCLIはサーバー側クォータモジュールに含めません。[第三者の通知](../../backend/internal/server/SUBSCRIPTION_THIRD_PARTY_NOTICES.md)を参照してください。
