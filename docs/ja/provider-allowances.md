# プロバイダーのクォータと特典

**プロバイダー → クォータと特典**を開きます。上流アカウントを管理する画面です。顧客とチームの予算は引き続き「クォータポリシー」で管理します。

## 収集

クォータのキャッシュは推論の稼働確認から独立しています。ゲートウェイのリクエストはクォータAPIを呼びません。クラスタ内で調整されたバックグラウンド処理が、最大四つのアカウントを並列で更新します。更新間隔は30秒から一日で、初期値は60秒です。失敗しても前回成功時の値と日時を保持します。利用可能、使い切り、不明、照会失敗を区別します。10分を超えたデータ、必須ウィンドウの欠落、経過したリセット日時は空き容量の根拠にしません。

サブスクリプションは既存のアダプターを使います。APIキーには別の収集元を設定できます。Fusecode、DeepSeek、Moonshot、OpenRouter、StepFun、AiHubMix、ModelScope、GLM/Z.ai、Kimi Code、OpenCode Go、MiniMax、Command Code、Ollama、Mistral、NewAPI、Sub2API、およびVolcengine・Alibaba・Tencentのクラウドプランのプリセットがあります。提供元が照会を許可するキーと権限が必要です。Tencentではプランを混同しないようTeamIdを指定します。Mistralはキーの種類を確認してAPIまたはVibeの予算を選びます。StepFunのWebプランは暗号化ヘッダー内の有効なセッションが必要です。

Fusecodeはプリセットを選ぶか、Magpieの次の設定を入力します。

```text
URL: https://fusecode.ai/v1/usage
Expression: $remaining; Week: subscription.weekly_usage_usd / subscription.weekly_limit_usd %; Month: subscription.monthly_usage_usd / subscription.monthly_limit_usd %
```

ラベル、複数部分、通貨、割合、算術、集合の絞り込みと `sum`、`min`、`max`、`count` に対応します。一部だけ読めない場合はその部分を不明にし、すべて読めない場合は照会失敗にします。構造化ウィンドウには使用量、上限、単位、リセットと期限、対象・除外モデル、プールの所属を保存します。提供元が返さないリセット日時は補いません。

アカウントのキー、専用の暗号化トークン、暗号化ヘッダーを使えます。URLとヘッダーの `{key}` は実行時に置き換えます。保存後のヘッダー値は伏せられます。専用トークンは空欄で維持し、削除を選ぶと消去します。既存のURL、DNS、リダイレクト、プロキシ制限を適用します。クラウド署名の送信先は固定です。Alibabaのコンソールトークンは暗号化して20分間キャッシュします。

## 使用と特典の方針

モデルとアカウントの選択を別々に設定します。並べ替えと停止の対象は、プロジェクトとキーが許可されたルート、モデル、優先度の候補だけです。クォータ優先、期限優先、使用量が少ない順、使い切ってから切り替えの四方式があります。初期値は既存の順序を維持します。

アカウントまたはウィンドウの上限で、提供元の上限より前に停止できます。金額は報告された単位のまま扱います。参考ウィンドウは明示した上限以外には使いません。プールの上限は所属モデルだけに適用します。ウォレットの消費上限は独立した永続カウンターで管理します。チャージ、古い観測、再起動、履歴の削除では消費量が戻りません。リセットのないウォレットはUTCの日単位です。

クレジットの方針は既存動作、禁止、許可、優先、最後に使用です。同じ許可済みルートと優先度の範囲で適用します。クレジットや自動リセットでユーザーの上限を回避できません。

Codexの自動リセットは初期状態で無効です。週のクォータを使い切った場合、カードの期限前、または両方を選べます。週の使い切りには実際の呼び出し失敗と、そのリクエストで許可された候補だけを記録した最近の実行記録が必要です。利用可能または不明の候補が残る場合は消費しません。期限前の使用はウィンドウに使用量がある場合だけで、期限の近いカードを優先します。初期値は30分前、週一回です。永続的な予約と既存の冪等実行器で重複消費を防ぎます。結果が不明なら自動再試行を停止します。操作記録は画面で確認できます。

手動残高はバックグラウンドで計算し、設定の版を確認したキャッシュから読み取ります。計算失敗時は前回の値と取得時刻を保持し、古い値や未計算の値は不明として扱います。手動ウォレットは開始残高、期限付き付与額、定期補充、繰り越しに対応し、期限の近い付与額から消費します。推定から差し引くのはゲートウェイに記録された提供元原価だけです。外部の消費は含めません。米ドル以外は換算率を指定します。共有ウォレットは明示的に選択し、元のアカウントの同一性に固定します。残高が同じだけでは共有しません。共有の手動ウォレットは関連アカウントのゲートウェイ消費を合計し、モデル上限は独立して扱います。アカウント認証またはAPIキーの置換時は古い設定と観測を消去します。

## 履歴、通知、API

変化のあった成功観測を45日間保持します。ウィンドウ別に推移を表示し、観測された残高減少から残り日数を推定します。異なる通貨とクレジット単位は合算しません。高使用率、低残高、リセット前の未使用クォータを通知できます。同じ期間の重複を防ぎ、回復やチャージ後に再び有効にします。既存の通知先を選ぶと配信し、未選択なら通知画面に記録します。送信前に永続的に取得するため、結果不明の自動重複配信はありません。

管理者APIにはプロバイダー権限が必要です。

- `GET /api/admin/provider-allowances` と `/presets`：キャッシュと収集プリセット。
- `GET|PUT /api/admin/provider-resources/{id}/allowance/config`：秘匿済み設定とリビジョンによる更新。
- `GET /api/admin/provider-resources/{id}/allowance/history` と `/events`：件数を制限した履歴と操作記録。
- `POST /api/admin/provider-resources/{id}/allowance/refresh`：上流の明示的更新。

プロジェクトAPIキーは `GET /v1/allowance?model=<alias>` を使えます。`wait_seconds=0..60` を指定するとキャッシュの更新を待ちます。許可済みルートの利用可否だけを集計し、提供元の識別情報、残高、設定は返しません。待機中に提供元を呼びません。

スキーマ拡張11は、設定、セッション、履歴、特典イベント、ウォレットカウンターと索引を追加します。凍結された採用ベースラインは変えません。環境変数の追加はありません。[データベースの進化](database-evolution.md)を参照してください。
