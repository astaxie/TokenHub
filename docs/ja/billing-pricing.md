# モデル価格変更とプラットフォーム明細

## モデル価格変更

プラットフォーム管理者は「コストガバナンス → コスト請求 → モデル価格変更」で下流モデルを選択します。現在のモデル価格を読み込み、チャットと Embedding の Token 単価を扱います。上流コストの試算は参考情報で、Provider の原価設定は変更しません。

1. 入力・出力・キャッシュ単価や時間帯と試算用量を設定します。
2. 「料金を試算」を選択します。実際のモデル課金ロジックを使い、価格や試算履歴を保存しません。
3. 「モデル価格に適用」で確認ダイアログを開き、対象モデル、新旧単価、時間帯を確認します。
4. 「価格変更を確定」で初めて保存します。キャンセルでは保存せず、送信中の重複操作を防ぎます。

新規リクエストには即時適用し、処理中のリクエストは受付時のモデル設定を保持します。試算後に価格や継承キャッシュ価格の根拠が変更された場合は適用を拒否し、再試算と確認が必要です。同じ変更リクエストの再送は再適用や成功監査の重複記録を起こしません。予約適用は本期の対象外です。

キャッシュ読み取りの空欄はモデルの既定推定ルールを使い、書き込みの空欄は既定の入力・書き込み単価を継承します。明示的な `0` は無料です。Provider の入力・出力・キャッシュ読み取りでは、空欄を未知、`0` を無料として保存します。未知の原価を下流料金で代用しません。既存の Provider モデルを再取込しても保存済み価格・時間帯・設定有無を維持し、カタログ情報のみ更新します。原価変更は在庫で明示的に編集します。

時間帯は曜日（0 = 日曜、6 = 土曜）、IANA タイムゾーン、開始を含み終了を含まない区間、入力・キャッシュ・出力単価の上書きを扱います。日をまたぐ区間は開始日に属し、重複しない最大 64 区間を設定できます。試算日時にはブラウザーのローカルタイムゾーンを表示し、各区間は指定タイムゾーンで判定します。Embedding の時間帯設定は未対応です。

「価格変更履歴」は実際に適用した変更のみを表示し、モデル・実行者・日時・新旧設定・有効な基本価格の根拠を直近 100 件まで保持します。独立したシャドー料金表の公開は廃止し、`/api/admin/billing/rate-cards` は 410 を返します。既存の根拠を削除せず、過去の料金も再計算しません。

## プラットフォーム明細

「コスト請求 → プラットフォーム明細」は請求コネクターなしで利用できます。月または任意期間を選び、下流料金と上流コスト見積もりを分けて表示し、Provider・リソースアカウント・モデル・プロジェクトで集計、明細のページ表示、CSV 出力が可能です。

- 下流金額は受付時刻で集計した計上済みの料金です。失敗・部分配信リクエストの計上済み料金も含め、内部再試行で二重計上しません。
- 上流見積もりは再試行を含む各試行の保存済み価格と使用量を使います。価格・使用量・完了・換算根拠の不足は確認待ちです。
- 既知小計には既知金額のみを含めます。未確認や過去の根拠不足があれば不完全と表示し、仕入先の確定額と扱いません。
- 過去の明細は保存済み金額と識別情報を使い、現在の単価で遡及再計算しません。
- 集計・明細・照合は共通の明細根拠を使用します。10000 件を超える場合は明示的なエラーとし、期間や条件の絞り込みが必要です。暗黙に切り捨てません。プラットフォーム検索は最大 366 日、個別の顧客・仕入先明細プレビューは従来の 93 日制限を保持します。

「顧客明細と粗利益」には既存の詳細プレビューを残し、モデルディレクトリと Provider 在庫からも対象を絞って開けます。顧客プロジェクトを明示して表示中のスナップショットを出力し、仕入先請求額と見積額は分けて表示して合算しません。

「外部照合」はコネクター請求とローカル上流コストを比較します。プラットフォーム見積もりにコネクターは必須ではありません。未知コストをゼロや下流料金で代用して照合せず、先に根拠を補完します。明示的な無料コストはゼロで比較できます。本期ではプラットフォーム明細の締め処理、PDF、外部請求書の手動取込を追加しません。

## 管理 API

| メソッド | パス | 用途 |
| --- | --- | --- |
| GET | `/api/admin/billing/models/{model}/pricing` | 現在の価格と同時更新検証用フィンガープリント |
| POST | `/api/admin/billing/preview` | `{card, usage, at, exchange_rate?}` を試算。下流には実際の課金ロジックを使用 |
| POST | `/api/admin/billing/model-pricing/apply` | `{card, fingerprint, request_id, confirmed:true}` を適用 |
| GET | `/api/admin/billing/price-changes` | 適用済み価格変更履歴 |
| GET | `/api/admin/billing/statements` | `kind=tenant/provider`、RFC3339 の `from/to`、条件・集計・ページ指定。`format=csv` で出力 |
| POST | `/api/admin/billing/statements` | 既存の顧客・仕入先・粗利益明細プレビュー |
| GET | `/api/admin/billing/evidence/{request_id}` | リクエストと上流試行の元の根拠 |

各 API はプラットフォーム管理者専用です。モデル単価と変更記録を同一トランザクションで保存します。CSV は認証情報・プロンプト・応答本文を含めず、数式接頭辞を無害化します。既存のスキーマ 4 を利用し、過去のマイグレーションを変更しません。リクエスト根拠は引き続き蓄積され、自動保存期限クリーンアップはありません。
