# Domain Docs

## Layout

single-context レイアウトを使用します。

- CONTEXT.md：リポジトリ全体のドメイン用語集。
- docs/adr/：リポジトリ全体のアーキテクチャ決定記録。

## Reading rules

コードを調査する前にルートの CONTEXT.md を読み、
次に docs/adr/ から作業に関連する決定を読みます。

将来 CONTEXT-MAP.md が存在する場合は、まずそのマッピングを読み、
関連コンテキストの CONTEXT.md とコンテキスト固有の ADR を読みます。

文書が存在しなくても、そのまま続行します。欠如を理由に作業を止めたり、
先回りして作成を提案したりしません。用語や決定が明確になった時点で、
domain-modeling が必要に応じて追加します。

## Vocabulary

Issue、提案、仮説、テストでドメイン概念を扱う際は CONTEXT.md の用語を使い、
明示的に避けるとされた同義語を使用しません。
テスト名は引き続き AGENTS.md の英語規則に従います。

必要な概念が未定義の場合は、不要な新用語を導入していないか検討します。
実際に不足している場合は domain-modeling の対応事項として記録します。

## ADR conflicts

提案が既存の ADR と矛盾する場合は、ADR 番号、矛盾する内容、
再検討する理由を明記し、既存の決定を黙って上書きしません。
