# データベース不要の UI 受け入れテスト

実際の Next.js コンソールを合成 API フィクスチャで動かします。Go やデータベースを起動せず、既存の開発サーバーも再利用しません。ページ操作とレビュー用画像に使用し、コンポーネントテストとバックエンド統合 E2E は別に維持します。

## ローカル実行

`frontend/` で `.nvmrc` の Node バージョンを使用し、`npm ci` を実行します。初回は `npx playwright install chromium` でブラウザーを導入します。

```bash
npm run test:ui
npm run capture:ui
# 変更対象のシナリオのみ実行：
npm run test:ui -- --grep customer-complete
npm run capture:ui -- --grep billing
# ビルドやサーバー起動なしで一覧を確認：
npm run test:ui -- --list
```

両コマンドは `.next-ui` にビルドし、`127.0.0.1:43210` で独立したフロントエンドを起動して同じ検証を実行します。`capture:ui` は画像を添付し、`ui-test-results/index.html` と `manifest.json` を生成します。HTML をローカルで開き、画像をクリックして原寸を確認できます。マニフェストにはコミット、未コミット変更の有無、テスト結果を記録します。次回実行で成果物が置換されるため、保存にはディレクトリ全体をコピーしてください。

ランナーは `next-env.d.ts` の生成された import のみを復元し、他の変更を維持します。`.ui-test.lock` で同じチェックアウトの UI 実行を排他制御します。ビルドや他のブラウザーテストは順番に実行してください。ポート使用中は他のサービスを再利用せず失敗します。中断後の古いロックは、UI ランナーが停止していることを確認してから削除します。

## 分離と証拠の範囲

`tests/ui/config.cjs` は API を `http://tokenhub-ui.invalid` に固定します。Playwright は宣言されたメソッドとパスをネットワーク送信前に処理します。未定義ハンドラー、不正な本文、想定外の外部要求、同一オリジン API へのフォールバック、WebSocket、未捕捉のページ例外はテストを失敗させます。Service Worker は無効です。通常のフロントエンド資源、文書、RSC はローカルに限定されます。クエリ文字列は既定で拒否します。必要な API は `MockAPI.define` に明示的な検証関数を渡してください。

各テストは独立したブラウザーコンテキスト、フィクスチャ登録表、合成管理者セッションを使用します。模擬書き込みは当該テスト内だけに存在し、後続の模擬読み取りに反映されます。製品の認証迂回や実行時 mock モードは追加しません。ランナーは継承されたバックエンド接続設定を除外します。

現行コンソールの業務 API 呼び出しはブラウザー内です。ブラウザーの interception はサーバー側 fetch を捕捉しません。将来サーバーコンポーネントに業務データが必要になった場合、明示的なテスト専用トランスポートを先に用意してください。実サービスに依存させず、実バックエンドへのフォールバックを追加しません。

この層が示すのは UI の動作です。金額のサンプル応答は課金計算、サーバー権限、トランザクション、永続化の正しさを証明しません。共有 TypeScript DTO による形状検証も、バックエンド契約テストの代用ではありません。

## シナリオの保守

- `fixtures/shell.ts` はシェルが必要とする読み取りを宣言します。実際に必要な場合だけ追加し、一律成功の空オブジェクトで未定義 API を隠しません。
- `fixtures/billing.ts` は既存の明細 DTO を使用します。ID、金額、日時、利用者は合成データとし、テストごとにコピーした小さな名前付きサンプルを使います。
- `scenarios/billing.ts` は明細状態を列挙します。`billing.spec.ts` と `pricing.spec.ts` は実際のコントロールを操作し、画面と関連リクエストを検証します。
- `harness.ts` は分離、固定日時・言語、共通キャプチャーを提供します。`isolation.spec.ts` は未定義ルート、不正メソッド・本文、ネットワークへのフォールバックを拒否することを検証します。

ページ変更時には正常系と、関連する空・ロード中・失敗・権限・長文状態を扱います。role/label による選択を優先し、同名コントロールは領域で絞ります。撮影前に状態を検証し、ロード状態は固定 sleep ではなく解放可能な応答で制御します。フィクスチャに本番の課金アルゴリズムを再実装しません。

初期範囲は顧客・仕入先・粗利益明細、未知とゼロ、空・ロード・エラー、表示中の CSV、フィルター変更後の無効化、モバイル操作、ベースブランチの価格プレビューとシャドー料金表公開です。以前の混合課金キャプチャー実験を踏まえていますが、未マージの価格改修ではなくチェックアウト中の製品を対象にします。

## 画像レビュー

日時、タイムゾーン、言語、ビューポート、アニメーションを制御します。フォント読み込みを待ち、対象領域を撮影します。ビューポートより高い領域は拒否し、内部スクロールによる切れを防ぐため明示的な位置で名前付きの分割ビューポート画像を撮影します。デスクトップは 1440×1000、モバイルのフォームと結果は各390×844です。テスト名と診断は英語、レビュー用ギャラリーの見出しは中国語です。ネイティブコントロールやシステムフォントは OS により異なります。

変更画像ごとに文字、操作入口、切れ、状態を確認します。成功・失敗を区別し、成功した実行のみを受け入れの証拠にします。必要に応じてギャラリーを共有し、実行画像はソースにコミットしません。

初期段階では CI ジョブ、画像ベースライン、自動画像比較、Storybook、MSW を追加しません。将来、固定ブラウザー・フォント・OS とレビュー済みベースラインでピクセル比較を導入できます。既存の Go、データベース、ブラウザー CI は変更せず、各契約の検証を継続します。
