# 自托管上游默认可接入，网络限制作为显式运维策略

TokenHub 面向私有部署，本机和内网模型属于正常接入场景。管理员输入地址后再配置 CIDR、修改环境变量并重启，会使正常接入过于困难。因此采用自动模式：允许具备 Provider 配置权限的管理员使用本机／普通私网 IP、localhost、宿主机别名、Docker 服务名和企业内网域名；获准本地目标支持 HTTP，并默认直连。未启用认证的兼容服务可不填写 API Key。普通租户推理 API Key 不获得配置任意上游的权限。

这一决定有意放宽旧版默认关闭本地访问的边界。已有非空私网清单继续限制范围；旧模板单独的 `ALLOW_LOOPBACK=false` 不再代表主动禁止，需保留旧限制的部署选择严格模式。严格模式恢复旧字面量例外规则；本地流量是否参与代理策略独立配置，继承环境模式仍遵循 NO_PROXY，要强制走代理需选择统一代理。

HTTP 域名必须在发送前全部解析为获准真实本地地址，实际连接固定使用同一批结果；公网 HTTP、特殊危险地址及跨源重定向继续拒绝。已启用的 Synthetic DNS 地址池不因落在私网段而获得 HTTP 或自动绕过代理的待遇。配置代理也不撤销 TokenHub 对目标的访问校验。这里调整了 ADR 0008 的“全部 Provider 使用统一出口”范围，保留单一代理、代理凭据保护以及代理故障不隐式回退的决定。
