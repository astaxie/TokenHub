# 无数据库 UI 验收

这套测试使用真实 Next.js 控制台和合成 API 样本，不启动 Go 或数据库，也不复用已有开发服务。用于页面交互检查和验收截图；现有组件测试、后端集成 E2E 独立保留。

## 本地运行

在 `frontend/` 下使用 `.nvmrc` 指定的 Node 版本，执行 `npm ci`，首次执行 `npx playwright install chromium` 安装浏览器。

```bash
npm run test:ui
npm run capture:ui
# 只运行受影响的场景：
npm run test:ui -- --grep customer-complete
npm run capture:ui -- --grep billing
# 只列出场景，不构建或启动服务：
npm run test:ui -- --list
```

两条命令都会构建到 `.next-ui`，并在 `127.0.0.1:43210` 启动独立前端，执行同一套断言。`capture:ui` 额外保存截图，生成 `ui-test-results/index.html` 和 `manifest.json`。本地打开 HTML，点击图片查看原图。清单记录源代码提交、工作区是否有未提交内容以及各项结果。后续运行会替换产物，需要留档时复制整个目录。

运行器恢复 `next-env.d.ts` 的生成导入语句，保留其他修改，通过 `.ui-test.lock` 阻止同一工作区的 UI 测试并发执行。同一工作区的构建和其他浏览器测试应顺序运行。端口占用时直接失败，不复用其他服务。异常中断后，先确认没有 UI 运行器存活，再删除残留锁。

## 隔离与证据边界

`tests/ui/config.cjs` 将 API 地址固定为 `http://tokenhub-ui.invalid`。Playwright 按声明的方法、路径拦截请求。缺失处理器、无效请求内容、意外外部请求、同源 API 回退、WebSocket 或未捕获的页面异常都会使自动测试夹具失败；Service Worker 被禁用。正常前端资源、页面和 RSC 请求保持在本地。查询字符串默认被拒绝；需要查询参数的接口须向 `MockAPI.define` 提供明确的校验函数。

每个测试独立创建浏览器上下文、样本注册表和合成管理员会话。模拟写入只存在于本测试内，后续模拟读取反映同一状态。不向产品加入认证绕过或运行时 mock 模式；运行器会移除继承的后端连接配置。

当前控制台在浏览器内请求业务 API。浏览器拦截无法拦截服务端 fetch：将来若服务端组件需要业务数据，先提供明确的测试专用数据传输方式，再增加场景。UI 测试应保持不依赖真实服务，不添加真实后端兜底。

这套测试只证明 UI 行为。样本返回一个金额，不代表计费算法、服务端权限、事务或持久化已验证。共用 TypeScript DTO 可以检查样本形状，但不能代替后端契约测试。

## 维护场景

- `fixtures/shell.ts` 声明页面外壳必需的读取。只有页面确实需要时才增加接口；不存在一律返回成功空对象的兜底。
- `fixtures/billing.ts` 复用现有对账单 DTO。ID、金额、日期和身份全部使用合成数据，每个测试复制样本，保持样本小而有明确名称。
- `scenarios/billing.ts` 列出参数化对账单状态；`billing.spec.ts`、`pricing.spec.ts` 操作真实控件，并断言页面结果和相关发送请求。
- `harness.ts` 安装隔离、固定时间与语言，并提供统一截图方法；`isolation.spec.ts` 验证隔离本身会拒绝缺失接口、错误方法、无效请求内容和网络回退。

修改页面时覆盖正常路径，以及相关的空、加载中、失败、权限或长内容状态。优先使用角色、标签定位；重复控件限定到对应区域。先断言页面状态，再截图；通过可释放的响应控制加载状态，不使用固定等待。样本中不重新实现生产计费算法。

首批覆盖客户/供应商/毛利对账单、未知与零金额、空/加载/错误状态、当前预览 CSV、筛选后失效、手机操作，以及基线分支的计价预览/影子价目发布流程。图集吸收了之前混合计费截图实验的做法，但针对当前检出的产品，不依赖尚未合并的调价改版。

## 截图验收

固定时间、时区、语言、视口和动画设置。截图方法等待字体加载并截取相关区域；高于视口的区域会被拒绝，须明确滚动位置并生成命名的视口分段截图，避免内部滚动造成截断。桌面场景使用 1440×1000，手机表单和结果分段使用 390×844。测试名称和诊断使用英文，面向人工审阅的图集标题使用中文。原生控件和系统字体可能随操作系统变化。

逐张检查变化截图的文字可读性、操作入口、裁切和状态。区分通过与失败的运行，只有通过的结果才能作为验收证据。需要时提供生成的图集，不把运行截图提交到源代码。

第一阶段不增加 CI 任务、图片基线、自动截图比较、Storybook 或 MSW 依赖。后续可以在固定浏览器、字体和操作系统环境下增加经过审阅的像素基线。现有 Go、数据库和浏览器 CI 检查保持不变，继续验证各自契约。
