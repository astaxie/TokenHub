# 管理总览与历史告警

总览返回元数据计数、项目和 Provider 配置，以及最近 20 条告警。完整模型定义由使用它们的页面按需加载。控制台通过 `GET /api/admin/model-search?q=...` 搜索模型，每次最多返回 20 条。

## 历史统计

`GET /api/admin/overview` 中的全历史用量与请求总数来自 `overview_totals`。SQLite 全局总计占两行。PostgreSQL 使用事务保留分片，通过非阻塞 advisory 协调让活跃写事务更新不同分片，读取时跨分片求和。分片数量取决于峰值并发写事务。单个分片可保留更正产生的正负贡献，分类筛选在跨分片汇总后进行。全历史分类统计使用同一投影中的模型、Provider 和资源账号维度，并独立于总览元数据加载。权限统计保留项目、API key 和调用归属用户的组合，同一记录命中多个 OR 权限条件时仅计算一次。独立的 `GET /api/admin/usage/summary` 仍使用原有 SQL 聚合；按时间范围的报表与时间序列继续使用现有日期窗口和分析查询。

SQLite 迁移 12 和 PostgreSQL 迁移 13 增加汇总表、原始记录投影标记、索引和数据库触发器。插入、相关字段更正和删除在原数据库事务内维护投影，也覆盖当前 Go 进程之外的写入。每条原始记录仅投影一次，已投影记录更正时先扣减旧贡献再增加新贡献。

历史记录通过数据回填 ledger 在线分批处理。已索引的待处理标记充当持久游标，每批在同一事务内分组汇总、标记覆盖记录并记录处理数量。集群 lease 协调多个实例，关闭时取消任务并释放自身 lease。现有后台调度入口负责启动该任务。PostgreSQL 迁移 14–17 分别以并发方式建立大表索引，各自支持重试和精确定义校验。共用迁移 18 增加持久完成状态，已完成的投影直接读取完成标记。

回填期间首页保持可用，`summary_status.state` 为 `preparing`。全局运营角色可见已处理记录数，受限角色仅看到准备状态。每次刷新完成后三秒再发起下一次请求。两个来源均完成覆盖后展示完整总数。新数据库可立即提供完整统计。

成功汇总按有效权限范围缓存 15 秒，并发刷新共享查询。单个请求取消时停止等待，最后一个等待者取消共享查询。最多缓存 128 个不同权限范围，查询期限为 10 秒。刷新失败时，最多返回 60 秒前的成功结果，状态为 `stale` 并标明计算时间；超过后统计区显示独立错误，其他页面数据继续可用。分类查询失败时清空旧分类数据并显示错误。分类统计准备中时清空旧数据，沿用总览的准备状态。

## 历史告警

`GET /api/admin/alerts` 返回 `data`、`page`、`page_size` 和 `total`。默认每页 50 条，强制上限为 100 条。支持 `project_id`、`severity`、`from`、`before`。时间使用 RFC 3339，包含 `from`，排除 `before`。按创建时间和 ID 降序排列。

控制台历史列表使用服务端分页，取消过期请求，分别展示筛选后的总数和当前页记录。当前页因历史记录清理而失效时，自动重新加载最后一个有效页。项目配额事件次数与最近发生时间通过 `GET /api/admin/project-quota-events` 独立查询，统计可见项目的全部已留存历史。全局运营角色获得请求日志与告警的合计；受限角色仅获得其有效权限内的请求日志统计。

## 验证

后端回归覆盖响应上限、筛选、重叠权限、更正、删除、回填续跑、取消和旧缓存期限。PostgreSQL 投影测试加入 CI。`overview-bounds` 界面场景覆盖正常、准备中、失败、模型搜索和历史告警分页。

可选测试 `TestOverviewRepresentativeScale` 和 `TestPostgresOverviewRepresentativeScale` 准备 300 万条用量、300 万条请求、10 万条告警和 300 个模型。回填完成后分别以冷缓存和热缓存、10 并发调用记录 p95 与每次累计分配量，要求 p95 小于 1 秒。启用 `TOKENHUB_OVERVIEW_SCALE=1`，PostgreSQL 还需 `TEST_POSTGRES_URL` 和 `integration` build tag。用量与请求时间固定为 2026-01-01，当前近期趋势窗口为空；这些结果覆盖历史投影读取及空近期趋势查询，不代表有数据的近期流量查询或实时写入吞吐。结果对应固定测试环境，生产峰值 RSS 和既往 OOM 的归因仍需现场证据。

SQLite 金额投影使用补偿求和保留低位贡献。累计值超出 SQLite 整数范围或金额累计出现非有限值时，统计读取退回原始 SQL 汇总，继续使用缓存和查询期限。这一异常数值路径会扫描历史，优先保证原始记录持久化和更正后的统计准确性。PostgreSQL 的汇总使用 NUMERIC。

现有 v0.11.0 运行器会拒绝新的迁移 ledger 条目。部署前需安排具备兼容支持的桥接版本，才能保证升级后的应用版本回退。管理前端需与本次后端同步更新。
