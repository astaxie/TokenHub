# 分时与缓存计价

## 当前行为

模型及 Provider 模型的分时规则支持 `weekdays`（0 为周日，6 为周六）、IANA 时区、RFC3339 生效区间，以及普通输入、缓存读取、普通/5 分钟/1 小时缓存写入、输出单价覆盖。省略星期表示每天。跨午夜按开始日归属，边界起含止不含；开始与结束时刻相同表示所选日全天。

最多配置 64 个时段。生效区间相交时，每周时段不能重叠，并须使用同一时区。剩余时间使用默认价格。省略时段单价表示继承，明确填写零表示免费。

模型目录缓存读价填写零后，保存和回读仍为免费。模型 HTTP PATCH 省略单价时保留原值。发送 `cache_read_price_usd_per_1m: null` 可恢复旧估算策略，也可提交零单价及 `metadata.cache_read_price_configured: "false"`。只修改无关元数据不会取消免费状态。缓存写入 PATCH 的零表示免费，null 表示继承。价格折扣不会减少实际 Token 配额或 TPM 计量。

租户旧计价仍使用准入时价格。通用路由的每次上游尝试在发送前固定 Provider 模型配置，请求中途改价不会重算该次成本。新证据会明确表示上游缺价，不虚构已知成本。

## 精确影子计价

平台管理员可在“成本账单 → 精确计价与影子核对”选择租户模型或 Provider/模型组合，填写十进制字符串单价和时段，预览指定时刻费用，再发布不可变影子版本。表单要求先预览成功；修改配置后旧预览失效。每个时段至少选择一天。

影子价目只为新请求记录比较结果，尚不替换当前收费或预留预算。旧价格标记为 `legacy_float_configuration`；转成十进制字符串不等于补造历史精确依据。当前适配器用量的字段存在性和供应商计费时间规则仍未确认。用量矛盾、缺价、缺 usage、交付不明确会保留待核实状态，不代表已与供应商账单对齐。

单价最多 18 位整数、12 位小数。精确分项求和后统一按 half-even 舍入到 12 位，换汇从未舍入总额计算。缺汇率时原币金额仍保留，USD 缺省。租户价目为 USD，目前要求全部六个基础分项；尚无独立“不适用”状态。

以下接口仅向平台管理员开放：

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| GET、POST | `/api/admin/billing/rate-cards` | 列出或发布不可变影子价目 |
| POST | `/api/admin/billing/preview` | 预览 `{card, at, usage, exchange_rate}` |
| POST | `/api/admin/billing/exchange-rates` | 发布 `{currency, rate, source, effective_from?}`，方向为 1 原币兑 `rate` USD |
| GET | `/api/admin/billing/evidence/{request_id}` | 查询准入、尝试准备及影子结算证据 |

价目包含 `kind`（tenant/provider）、`target`（模型名或 `provider_id:upstream_model`）、`currency`、`source`、可选 `effective_from`、`rates` 和可选 `periods`。分项键为 `input`、`cache_read`、`cache_write`、`cache_write_5m`、`cache_write_1h`、`output`；时段将上述时间规则与 `rates` 覆盖组合。选择最新适用生效时刻，同一数据库时刻立即发布的版本按 revision 排序。历史快照保持原版本，汇率在每次尝试固定。价格和汇率发布均记录管理员审计事件。

新证据保存项目/Key 的 ID 和名称、用户/团队/成本中心 ID、准入 UTC 日/月，以及逐次 Provider/资源归属、价格、汇率、上游请求 ID 和结果，不保存 prompt、响应正文或凭据。只有准备记录而无完成证据时表示“可能已发送”，不能自动重发或按免费处理。影子结算与现有请求结算同事务提交，每个服务端请求 ID 只有一份基础记录。

## 迁移与待办

数据库扩展版本 4 新增 `metering_entries` 和索引，不重写历史用量或基线迁移。运行时要求结构版本 4，正常启动负责升级旧库。恢复或回滚须保留证据表并使用兼容程序，当前没有自动证据保留期限清理。

本次是计价和影子证据增量。跨范围持久金额预留、实际精确扣费、协议字段存在性证据、崩溃恢复及 24 小时人工队列、不可变调整、普通用户证据界面、不适用分项以及既有对账模块关联仍待后续完成。预留舍入辅助函数已测试，但尚未成为准入控制。绕过通用路由尝试循环的后台通道尚无等价逐次证据。本次未验证生产 PostgreSQL 并发或供应商账单一致性。

模型价格更新会拒绝非有限值或负数基础单价。旧 Provider 零值缺少配置依据时，按用量分项保持未知，继承的缓存写入价也遵循此规则；明确的影子价目或时段覆盖可以声明免费。即使精确价目可计算影子费用，缺少旧价依据时 `legacy_usd` 仍为空。`tokenhub db verify` 校验扩展后的结构，包括证据表和索引；旧库接管仍使用未改变的历史基线。

## 费用对账单

平台管理员可以从计费页、对外模型行或 Provider 模型成本设置打开对账单。选择日期范围（结束日不含当天，最多 93 天）和时区，预览后导出 CSV。导出使用当前预览的同一份数据；修改条件会清除预览。对账单不表示已确认或已收付款。

下游要求填写客户名称并明确选择项目。名称不创建租户或授予权限。项目、历史团队和 API Key 提供明细，导出不含供应商身份和采购价格。历史团队归属采用准入快照。

上游展示每次调用尝试，包括重试。本地估算与供应商金额按来源、币种分别汇总，不能相加。供应商行保留外部行号、数量／单位、原币种和时区。跨所选期间的记录保留全额并标记，不自动分摊。没有分摊依据时，不将供应商账单归入客户项目。

预计毛利采用已记录客户费用减对应请求的本地成本，包含跨月重试；它不代表净利润或现金结余。存在未知成本、缺失汇率、历史依据不足或未完成尝试时，不显示毛利数值。供应商总额不替代请求成本。影子价目不改变实际客户收费。历史价格能解释已记录金额时才展示；没有快照的旧记录采用完成时间并标记依据不足。历史上游零成本表示未知，不能用售价替代，也不能证明免费；具备零价证据的记录仍为零。请求收费和确认、争议、支付流程保持不变。

只读接口 POST /api/admin/billing/statements 仅允许平台管理员调用。JSON 参数：side（tenant/provider/margin）、from、to（YYYY-MM-DD）、timezone、customer、project_ids，可选 provider_id、resource_id、model。下游必须填写客户与项目；下游和毛利拒绝供应商筛选。上游模型筛选使用上游名称，其他使用对外名称。结果超过 10,000 行会报错而非截断，请缩小范围或筛选条件。

外部账单在写入时固化 Provider 和资源归属。历史记录会在修改或删除连接器之前，以及首次生成供应商对账单之前，使用升级时可用的归属信息回填一次。重复导入保留原始快照；升级前已经发生的配置变更无法还原。期间筛选会在应用行数上限之前排除恰好结束于开始边界的非瞬时记录。历史零金额缺少成本证据时，对账以 `reconciliation_provider_cost_unknown` 失败；明确零成本必须有已知成本标记，或匹配的持久化版本化价格及零费用证据。未知成本不能与供应商零金额账单匹配。
